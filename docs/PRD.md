# 电商运营智能 Agent 产品需求文档（PRD）

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | Shop Agent（暂定） |
| 文档版本 | v0.1（MVP） |
| 更新时间 | 2026-09-11 |
| 产品定位 | 面向电商运营人员的 AI 工作助手 |
| 技术方向 | Web 前端、FastAPI 后端、DeepAgent 服务、langChain、langGraph（Python 3.12）|

> **业务假设**：MVP 以“分析经营数据 + 生成运营方案”为核心。真实业务数据、广告平台和电商平台的写入操作在接入后均须经过人工确认。

## 2. 背景与目标

电商运营工作中的数据分散在商品、订单、流量、推广及内容平台。运营人员需要频繁完成数据查询、经营诊断、文案创作和活动规划等重复性工作；现有报表能提供数据，却很难快速回答“为什么下降”“下一步做什么”和“如何落地”。

Shop Agent 让运营人员以自然语言获取经营洞察、生成运营内容和方案，降低分析和内容生产成本。

### 2.1 产品目标

1. 将常用经营数据查询和诊断收敛到多轮对话中。
2. 基于真实数据生成有依据且可追溯的运营建议。
3. 提升商品标题、卖点、活动文案等内容生产效率。
4. 为运营方案生成明确的执行建议和复盘依据。
5. 保障数据使用与外部平台操作安全，避免 Agent 未经确认执行高风险操作。


## 3. 用户与场景

### 3.1 用户角色

| 角色 | 核心诉求 | 主要使用内容 |
| --- | --- | --- |
| 运营专员 | 查数据、写内容、制定日常动作 | 对话问数、内容生成 |
| 运营负责人 | 诊断经营问题、制定活动方案、复盘团队执行 | 查看团队数据与汇总指标 |

### 3.2 核心场景

1. **经营问数**：询问 GMV、订单量、转化率、客单价、退款率、流量来源等指标及同比/环比变化。
2. **经营诊断**：询问商品、渠道或活动指标下滑的可能原因，并得到基于数据的排查建议。
3. **商品内容创作**：基于商品信息、目标人群和平台规范生成标题、卖点、详情页文案。
4. **活动策划**：根据活动目标、预算、货品和周期生成活动方案、节奏与风险提示。
5. **活动复盘**：活动结束后汇总数据、对比目标并生成复盘初稿。

## 4. 产品范围

- 支持多轮文本对话、会话保存和流式回答。
- 支持运营活动、玩法规则等资料在团队或私有空间中上传、解析、预览、下载和知识库问答。
- 支持按需检索公开互联网资料，用于最新平台政策、行业动态、竞品公开消息和市场趋势。
- 接入模拟数据或首个数据源，支持核心经营指标查询。
- 支持时间范围、商品和渠道维度的数据筛选与趋势比较。
- 支持商品标题、卖点、活动文案与运营方案生成。
- 展示数据来源、统计口径、查询范围和生成内容的引用依据。
- 支持会话审计和基础运营分析。
- 支持本地账号注册、登录和退出；会话及后续长期记忆严格归属于登录用户。


## 5. 业务流程

```text
运营人员提出问题或任务
        ↓
Agent 识别意图、时间范围与目标
        ↓
条件不足时，追问一个关键条件
        ↓
调用数据查询 / 知识库 / 联网搜索 / 内容模板等工具
        ↓
生成带数据依据的洞察、内容草稿或行动建议
        ↓
用户复制、导出或继续优化
        ↓
记录引用数据与运行审计
```

## 6. 功能需求

### 6.0 账号与数据隔离

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-00 | 用户可使用账号、显示名称和密码注册，并在注册后自动登录。 | 账号仅允许字母、数字、下划线和短横线；密码不少于 8 位；重复账号被拒绝。 |
| FR-00.1 | 用户可登录、退出并恢复有效登录状态。 | 登录失败不区分账号或密码错误；退出后当前令牌失效；令牌过期后前端要求重新登录。 |
| FR-00.2 | 会话、消息、会话上下文和运行审计仅能由其所属用户访问。 | 以其他用户令牌访问已知会话 ID 时返回“会话不存在”；会话列表只返回当前用户数据。 |

> 本期账号用于本地或单机部署中的数据隔离。系统包含最小管理员角色：管理员管理团队资料；普通用户管理自己的私有资料。尚不包含邮箱验证、找回密码、企业级组织、项目成员或单点登录。

### 6.1 会话与上下文

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-01 | 用户可创建会话、输入文本并接收流式回答。 | 空消息不可发送；生成时显示加载状态和停止入口。 |
| FR-02 | 系统保存并受控装配会话上下文。 | 同一会话中可继承用户明确确认的活动、时间范围、指标和分析目标；支持重置条件；不从模糊表达中猜测条件。 |
| FR-03 | 用户可查看、重命名和删除自己的历史会话。 | 会话按最近更新时间排序；删除后用户端不可恢复。 |
| FR-04 | 用户可停止生成并重试失败消息。 | 已输出文本保留；后端停止对应生成任务。 |

### 6.2 经营数据查询

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-10 | Agent 可识别 GMV、订单量、支付转化率、客单价、退款率、访客数等常见指标查询。 | 每次数据回答显示指标名称、数值、时间范围和统计口径。 |
| FR-11 | 支持按商品、类目、渠道和时间范围筛选数据。 | 默认时间范围须在回答中说明；无结果时清晰提示。 |
| FR-12 | 支持环比、同比及趋势查询。 | 比较基准、公式和缺失数据情况清晰展示。 |
| FR-12A | 支持单个问题中的多时间范围指标对比。 | 系统将用户明确提到的活动期或日期范围拆为最多 4 个受控查询单元；每个单元只执行已审核的指标模板，并展示各区间数值及相对首个区间的确定性差异。超出上限时不执行部分查询，提示用户拆分问题。 |
| FR-13 | 数据查询结果关联数据源和查询时间。 | 用户可查看来源摘要；日志保留工具调用记录。 |
| FR-14 | 数据源不可用时提供友好降级。 | 不编造实时数据，说明不可用原因并支持重试。 |

### 6.3 运营资料知识库

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-15 | 用户可上传运营活动、玩法规则等资料至私有资料空间。 | 首期支持 PDF、DOCX、Markdown、TXT；单文件最大 20MB；拒绝空文件和不支持格式；私有资料仅上传者可见，且默认加入其问答检索。 |
| FR-15A | 管理员可上传和删除团队资料。 | 全部已注册用户可查看、预览、下载团队资料；普通用户上传团队资料或删除团队资料时返回拒绝。 |
| FR-15B | 用户可独立勾选可见资料是否参与问答检索。 | 团队资料默认不勾选；任一用户的勾选或取消不影响其他用户；未勾选资料不得进入该用户的知识库 RAG 候选集。 |
| FR-16 | 系统异步解析原文件、切分文本并建立本地向量索引。 | 上传接口在原件持久化和索引任务创建后即返回；前端展示排队、解析、向量化进度、完成或失败状态。Worker 重启时未完成任务可恢复；临时失败最多重试 3 次，完成后才显示“索引已完成，可检索”。 |
| FR-17 | 用户可在知识库中查看提取文本预览、下载或删除原始文件。 | 私有资料仅上传者可删除，团队资料仅管理员可删除；删除时同时删除文件、索引任务、片段、向量及用户勾选记录，操作前二次确认。 |
| FR-18 | 对话自动按需检索当前用户已选择的知识库资料。 | 主 Agent 通过受控指标与知识库工具完成检索；系统先进行本地语义意图路由：明确的数据问题只调用指标工具，明确的资料问题只调用知识库工具；综合或低置信度问题调用两者，任一类未命中不阻断另一类回答。 |
| FR-18B | 路由结果必须转换为代码级执行计划后再生成回答。 | 指标、知识库、联网和综合路由分别对应固定必调工具；系统先执行并校验计划，再将实际结果交给模型总结。 |
| FR-18C | 每种受控工具在单轮内最多真实执行一次，并校验成功结果的引用类型。 | 模型重复请求同一工具时被拒绝且留存 `tool_call_limit_reached`；指标、知识库、网页成功结果分别具备 `metric:*`、`knowledge_chunk:*`、HTTP(S) 引用 ID。 |
| FR-18D | 知识库与指标定义检索采用多路混合召回。 | 原始问题始终参与；最多追加 2 条不改变事实、时间、活动或对象的检索改写；同一轮的指标与知识库检索复用同一份问题向量和改写结果。知识库的每条 Query 由 PostgreSQL 分别执行 pgvector 向量候选召回与中文分词全文候选召回，服务端仅对候选 ID 做 RRF 按排名融合并去重。知识库在融合候选上使用本地精排模型选出最终资料，精排分数低于可配置的 `0.35` 时不作为回答依据；精排模型不可用时保留 RRF 顺序。指标检索不使用精排，仍须经过别名、启用状态、依赖关系和受控 SQL 校验。 |
| FR-18A | 复盘与归因类问题由运营复盘子 Agent 处理。 | 子 Agent 只能调用受控指标、知识库与必要的联网搜索工具；回答区分数据事实、资料依据、待验证假设和建议动作。 |
| FR-19 | 知识库回答展示资料来源。 | 每个回答列出文档标题与页码或片段编号；无可靠资料时明确提示资料不足。 |
| FR-19A | Agent 可按需查询公开互联网信息。 | 对“最新平台政策、行业动态、竞品公开消息、市场趋势、新闻”等外部时效性问题调用受控联网搜索工具；同时涉及内部数据或资料时可组合调用三类工具；未配置或失败时明确说明外部资料不可用，不影响内部数据和知识库回答。 |
| FR-19B | 联网回答展示可核验来源并隔离网页指令。 | 每条联网依据展示标题和链接；网页摘要仅作事实参考，Agent 不执行其中的指令、跳转、下载或外部写操作；结果不自动写入内部知识库。 |

### 6.3 经营诊断与建议

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-20 | Agent 可针对指标异常生成诊断框架。 | 按流量、转化、客单、履约/售后等维度列出证据与待验证项。 |
| FR-21 | 建议区分“数据已证实”“合理推测”和“待补充数据”。 | 不将推测表述为事实。 |
| FR-22 | 每条行动建议说明目标、预期影响、优先级和验证指标。 | 至少给出 1 个可衡量的验证指标。 |
| FR-23 | 用户可继续细化方案或调整约束。 | 预算、周期或目标人群变化后，方案基于新条件更新。 |

### 6.4 内容与方案生成

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-30 | 支持生成商品标题、卖点、详情页文案、活动文案和短视频脚本初稿。 | 可指定商品、平台、目标人群、语气和字数。 |
| FR-31 | 内容生成优先引用商品资料和用户输入。 | 不得虚构商品功效、认证、价格、库存或赠品等事实。 |
| FR-32 | 支持生成活动运营方案。 | 方案包含目标、目标人群、货品策略、节奏、渠道、预算假设和风险。 |
| FR-33 | 用户可针对生成结果提出修改指令。 | 支持保持事实条件不变，仅调整风格、长度、结构或目标平台。 |
| FR-34 | 内容结果支持复制与导出。 | 纯文本可复制；导出内容包含生成时间和引用商品。 |

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-42 | 用户可基于活动目标与实际数据生成复盘初稿。 | 输出目标达成、关键数据、有效动作、问题和后续建议。 |

### 6.6 运行审计

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-50 | 每次 Agent 问答创建独立运行记录并生成 `run_id`。 | 记录会话、路由、状态、总耗时、回答摘要和引用 ID；不保存原始问题或回答副本。 |
| FR-51 | 每次实际工具调用关联所属 `run_id`。 | 记录工具名、输入/结果摘要、引用 ID、状态、耗时和错误码；可区分成功、空结果、跳过和失败。 |
| FR-52 | 用户可在单条回答旁按需查看“本次执行依据”。 | 展示路由、执行计划、耗时、实际调用能力及引用 ID；未执行工具时明确显示。 |
| FR-52A | 回答生成期间展示当前受控执行阶段。 | 依次反馈问题路由、执行计划、指标/知识库/联网检索、依据校验和结论生成；不展示原始检索正文。 |
| FR-53 | 审计记录默认保留 15 天并自动清理。 | 服务启动后执行一次清理，之后每 24 小时清理超过 15 天的运行及关联工具明细。 |
| FR-54 | Agent 不得自行执行外部平台写入操作。 | 一切写操作须由用户在目标平台或审批流程中明确确认。 |
| FR-55 | 必调工具缺少终态记录或成功结果缺少合法引用时，系统停止事实性回答。 | 返回明确的完整性校验失败说明，不基于不完整上下文生成数据、资料或网页结论。 |
| FR-56 | 系统维护固定的 Agent 离线评估集。 | 评估集覆盖 618、七夕、春季活动及资料/联网不可用场景；每次运行校验路由、执行计划、工具次数、引用类型与诚实降级行为，且不访问真实网络或生产数据。 |
| FR-57 | 系统记录本轮会话条件的确认、覆盖、清除和继承动作。 | 单条回答审计可查看实际采用的结构化快照及其本轮变化；仅保存结构化条件和来源消息 ID，不复制历史问题原文。 |
| FR-58 | 系统可使用最近一轮已完成回答处理“刚才”“为什么下降”等指代。 | 仅向回答生成层提供长度受限的结论摘要、`run_id` 和引用 ID；不参与路由、SQL 参数或知识库检索。 |

## 7. 页面与交互要求

### 7.1 运营工作台

- 左侧展示最近会话与“新建会话”入口；主区为对话内容。
- 左侧提供知识库管理入口；以“团队资料 / 我的资料”页签展示可见文件，支持勾选“加入问答”、查看处理状态、预览提取文本与下载原文件；管理员可选择上传至团队资料。
- 输入区由系统自动判断所需检索能力，并可重置本会话继承条件；回答并列展示指标和资料引用。资料范围由知识库管理中的“加入问答”选择控制。
- 每条已完成的 Agent 回答可展开“本次执行依据”，查看脱敏的会话条件、路由、工具状态、耗时和引用 ID。
- 首页提供示例问题，如“分析本周 GMV 环比下降原因”“生成一份秋季上新活动方案”。
- 数据类回答以指标卡、趋势摘要或表格展示，并标注数据范围和来源。
- 内容类回答提供复制、导出和继续改写入口。

### 7.2 审计展示边界

- 当前工作台仅展示单条回答的最小审计轨迹，不提供全量运行记录管理页面。
- 审计详情只展示问题/回答摘要、引用 ID 与工具摘要，不重复展示会话原文、文档正文或网页正文。

## 8. 数据需求

### 8.1 核心实体

| 实体 | 关键字段 |
| --- | --- |
| 经营指标 Metric | 指标名、数值、统计维度、时间范围、统计口径、数据更新时间 |
| 用户 User | `id`、唯一账号、显示名称、密码散列、`is_admin`、创建/更新时间 |
| 登录令牌 AuthToken | `id`、用户 ID、不可逆令牌摘要、过期时间、创建时间 |
| 商品 Product | `id`、名称、类目、价格、库存、属性、卖点、状态 |
| 会话 Conversation | `id`、用户 ID、标题、创建时间、更新时间 |
| 会话上下文 ConversationContext | 会话 ID、活动、时间范围、指标提示、分析目标及各字段来源消息 ID |
| 消息 Message | `id`、会话 ID、发送方类型、内容、数据引用、生成状态、创建时间 |
| Agent 运行 AgentRun | `id`（即 `run_id`）、会话/消息关联、问题摘要、会话条件摘要、结构化快照与变化、路由、状态、回答摘要、引用 ID、耗时、错误码、完成时间 |
| 知识库文件 KnowledgeDocument | `id`、所有者用户 ID、资料空间（团队/私有）、标题、原文件名、文件类型、存储路径、解析正文、索引状态、片段数、创建/更新时间 |
| 知识库片段 KnowledgeChunk | `id`、文件 ID、片段序号、文本、页码、标题、pgvector 向量、中文分词词项、向量模型标识 |
| 用户资料选择 UserKnowledgeDocumentSetting | 用户 ID、文件 ID、是否参与本人问答检索、创建/更新时间 |
| 工具调用 ToolCall | `id`、消息 ID、`run_id`、工具名、入参摘要、结果摘要、引用 ID、状态、耗时、错误码 |

### 8.2 数据原则

- 经营结论只可基于已接入的数据源生成。
- 每项数据型结论保留指标口径、时间范围和查询时间。
- 运行审计不保存原始问题和回答正文，只保存不可逆的长度/路由摘要、工具结果摘要与引用 ID。
- 运行审计及关联工具调用保留 15 天，服务启动后及每 24 小时自动清理过期记录。

### 10.1 Docker 部署要求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| DR-01 | 项目应支持通过 Docker 在单机环境部署。 | 提供前端、API 服务和 Agent 服务所需的镜像构建定义及 Docker Compose 编排文件。 |
| DR-02 | 一次部署应启动完整的 MVP 服务。 | 在配置完成后，执行 `docker compose up -d --build` 可启动全部必需服务。 |
| DR-03 | 服务运行参数通过环境变量注入。 | 提供不含真实密钥的 `.env.example`；模型、数据源和数据库连接等配置均可通过环境变量设置。 |
| DR-04 | 需要保留的数据不依赖容器临时文件系统。 | 会话等持久化数据使用挂载卷或外部数据服务；重建应用容器后数据不丢失。 |
| DR-05 | 容器应具备健康检查和基础故障定位能力。 | 核心服务提供健康检查接口；应用日志输出至标准输出，`docker compose ps` 可反映服务健康状态。 |
| DR-06 | 部署文档应描述首次启动、升级、停止和数据备份方式。 | 按文档操作可完成部署；文档明确端口、环境变量、数据卷及常见故障排查方式。 |

> MVP 采用 Docker Compose 进行单机部署；容器编排平台、高可用、自动扩缩容和跨主机部署不属于本期范围。

## 11. 验收场景

1. 运营人员询问“分析本周 GMV 环比变化”，系统返回数值、对比周期、统计口径与数据更新时间。
2. 用户继续询问“下降的主要原因是什么”，Agent 基于可用数据列出已证实变化、待验证原因和优先排查动作。
3. 用户要求“为商品 A 写 3 个小红书标题，目标人群是初入职场女性”，生成内容符合指定语气，且不虚构商品事实。
4. 用户要求制定双 11 活动方案，Agent 输出目标、货品策略、节奏、预算假设和风险。
5. 用户按商品、渠道和时间范围筛选数据时，系统返回对应范围的指标；无匹配数据时给出明确提示。
6. 数据源不可用时，Agent 明确说明无法获得最新数据，不生成虚构的指标或结论。
7. 配置示例环境变量后，可使用 Docker Compose 构建并启动服务；健康检查通过，重建应用容器后持久化数据仍可访问。
8. 用户上传 PDF 后，界面显示索引过程与完成状态，可预览、下载或删除自己的原件；问答仅可引用本人已勾选的资料来源。
9. 开发人员运行固定评估集后，618、七夕、春季活动的指标、资料和综合问题均通过预期工具路径；资料不存在和联网未配置时，系统保留空结果或跳过轨迹并明确说明资料不足。
10. 用户先提问“分析 618 活动的 GMV”，再提问“再看看订单量”；系统在审计中显示继承 618 活动期、覆盖指标为订单量，并以结构化起止日期执行受控 SQL。
11. 用户输入“查询 8/16–8/22 的 GMV”后再问订单量；系统识别日期范围、清除不再匹配的旧活动标签并继承该日期；用户可在输入区重置会话条件。
12. 用户 A 和用户 B 分别注册并登录后，只能看到各自创建的会话；B 使用 A 的会话 ID 请求消息、上下文重置或审计时均无法访问。
13. 管理员上传团队资料后，所有登录用户都能查看，但默认不参与问答；用户 A 勾选后仅 A 的问答可召回该资料，用户 B 未勾选时不得召回。用户 A 的私有资料对 B 不可见。

## 12. 用户长期记忆

### 12.1 范围

- 长期记忆按登录用户隔离，可跨会话使用；当前会话条件仍由 `ConversationContext` 管理。
- 仅支持“分析习惯”“回答偏好”“关注主题”三类偏好；不提供侧边栏或独立页面的手工管理。
- 不支持也不保存指标口径偏好、业务数据、完整聊天原文或未经用户确认的模型推测。

### 12.2 功能需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-59 | 用户可在会话中使用“记住 …”“忘记 …”“清除所有记忆”管理自己的长期记忆。 | 显式命令只作用于当前登录用户，不调用 Agent、RAG 或业务数据查询；清除不会影响历史会话和审计。 |
| FR-60 | 系统在每轮提问前按需采用不超过三条有效长期记忆。 | 回答偏好优先用于呈现；分析习惯仅在分析类问题中优先采用；长期记忆不能覆盖本轮明确问题和会话条件。 |
| FR-61 | 系统从有限的自然偏好表达中生成待确认候选，并在对应回答下方展示“记住 / 暂不”。 | 用户点击“记住”后才写入长期记忆；普通业务问题、指标口径和业务数据不生成候选；候选只对当前登录用户可见。 |
| FR-62 | 用户可在单条回答的运行审计中看到是否采用长期记忆。 | 仅展示采用数量和记忆 ID，不复制记忆正文到审计表。 |

### 12.3 交互与优先级

```text
本轮明确问题
  > 当前会话已确认条件
  > 用户长期记忆
  > 系统默认规则
```

“重置会话条件”只清除当前会话的短期条件，不会删除长期记忆；如需删除长期记忆，用户可直接在任意会话输入“忘记 …”或“清除所有记忆”。
